01 / The finding

Run one task on one model several times in the same batch and you get a cell. A cell is mixed when the same prompt, unchanged, both passed and failed inside that batch. Sampling uses the API defaults; nothing else varies.

Half of Sonnet 5's repeated coding cells are mixed, and two thirds of Haiku 4.5's. A benchmark that runs each task once would report a coin flip for a large share of these tasks, and call it a capability measurement.

02 / Two models, same 22 tasks

Every queued task runs once on each model, adjacent in the queue, so the comparison is paired within a batch. Tasks that no model fails are retired from the queue, so this is the frontier of difficulty for these two models, not a general capability estimate.

The gaps are not a smooth ranking. Haiku never once passes ops_stack_night_shift or cal_stack_week_planner in 84 attempts, and passes hard_csv_strict 4 times in 266 — while Sonnet clears each of them at 98% or better. Yet Haiku is the better model on three tasks, including a TTL cache simulation it passes 92% of the time against Sonnet's 75%.

03 / How agents actually fail

Coding failures are labeled by rerunning the submission: the first wrong case decides. Tool failures go to Claude Opus 5 with the trace and a replay diff against the reference solution, into a fixed nine-label taxonomy.

Tool-failure labelSonnet 5Haiku 4.5

Across 497 labeled tool failures there is not one hallucinated tool call and not one loop. These agents fail by misreading the policy they were given. Sonnet's characteristic failure is different from Haiku's: it does the work and then stops before the confirmation message the task required.

At less than half the pass rate, Haiku is still the cheaper route to a passing episode — but only where a checker can tell a pass from a failure and a retry is acceptable. On the five tasks it almost never passes, retries never converge and its expected cost is unbounded.

05 / What this does not show

No drift. Across 42 task-model pairs tested over seven paired batches, three came out below p = 0.05 for a change in pass rate between batches. Chance alone produces about 2.1. The instrument for catching serving drift is in place — every turn records the served model and request id — but the corpus needs more nights before that question can be answered.

No capability claim. Tasks were written and retired adversarially against these two models. Pass rates here describe the edge of what they can do, not what they can do in general.

One day dominates. Two back-to-back batches on Sep 21–22 contribute about 73% of the paired episodes, so the pooled rates lean on one day's serving conditions. The per-batch analyses above do not.
